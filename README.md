# Автотесты для API микросервиса Авито

Проект содержит автоматизированные тесты для проверки API микросервиса объявлений в рамках тестового задания на стажировку QA в Авито.

Покрыты позитивные и негативные сценарии, проверки авторизации и доступа, граничные значения и валидация данных.

**Стек:** Python 3, `pytest`, `requests`.

**Тестовый стенд:** `https://qa-internship.avito.com`

---

## Структура проекта

```text
├── TASK1.md                - решение задания 1 (дефекты по скриншотам)
├── tests/                  - директория с модулями автотестов
│   ├── test_e2e.py         - жизненный цикл, список объявлений, статистика
│   ├── test_security.py    - авторизация, контроль доступа, подмена ID
│   └── test_validation.py  - валидация полей, типы данных, граничные значения, XSS
├── conftest.py             - фикстура авторизации и очистка тестовых объявлений
├── test_data.py            - тестовые данные и граничные значения
├── BUGS.md                 - результаты исследования потенциальных дефектов API
├── TESTCASES.md            - описание 15 тест-кейсов API
├── requirements.txt        - зависимости проекта
└── README.md               - описание проекта и инструкция по запуску
```

## Инструкция по запуску

**1. Клонирование и переход в папку проекта**

Клонируйте репозиторий через Git или скачайте проект и откройте терминал в его корневой директории.

**2. Создание виртуального окружения**

```bash
python -m venv .venv
```

Активация для Windows (PowerShell):

```powershell
.\.venv\Scripts\Activate.ps1
```

Активация для macOS/Linux:

```bash
source .venv/bin/activate
```

**3. Установка зависимостей**

```bash
python -m pip install -r requirements.txt
```

**4. Проверка сбора тестов**

```bash
python -m pytest --collect-only -q
```

**5. Запуск всех автотестов**

```bash
python -m pytest -v --tb=short
```

Для запуска отдельных модулей:

```bash
python -m pytest tests/test_e2e.py -v
python -m pytest tests/test_security.py -v
python -m pytest tests/test_validation.py -v
```

Тесты обращаются к реальному тестовому стенду Авито. Для выполнения необходимо подключение к интернету.

## Покрытие тестирования

В `TESTCASES.md` описано **15 тест-кейсов**.

При запуске `pytest` собирается **17 проверок**, поскольку некоторые сценарии параметризованы или разделены на самостоятельные тесты.

| Модуль | Количество проверок | Что проверяется |
| :--- | :---: | :--- |
| `test_e2e.py` | 3 | Создание, получение и удаление объявления; список продавца; статистика v1 и v2 |
| `test_security.py` | 4 | Доступ без токена, подмена `sellerID` и `X-UserId`, несуществующий ресурс, удаление чужого объявления |
| `test_validation.py` | 10 | Граничные значения цены, некорректные типы, отсутствующие поля, статистика, длинное название и XSS-строка |
| **Всего** | **17** | |

## Тестовые данные и очистка

Для каждого теста фикстура `auth_session` регистрирует нового пользователя и получает Bearer-токен.

Объявления создаются с `sellerID` авторизованного пользователя. UUID созданных объявлений сохраняются для последующей очистки через `DELETE /api/2/item/{id}`.

Для проверки разграничения доступа отдельные тесты дополнительно регистрируют второго пользователя.

Очистка выполняется по завершении теста. Если сервер не отвечает или возвращает неожиданный статус, ошибка фиксируется. Поэтому при нестабильном соединении отдельные тестовые объявления могут остаться на стенде.

## Результаты тестирования

- **E2E:** 3 теста успешно прошли в одном запуске.
- **Безопасность:** 3 теста прошли, 1 завершился с результатом `XFAIL`.
- **Валидация:** все 10 проверок выполнялись успешно, но повторные полные запуски модуля сопровождались периодическими сетевыми тайм-аутами, поэтому стабильный результат `10 passed` без ошибок завершения пока не получен.
- **Сбор тестов:** `pytest --collect-only -q` обнаружил все 17 проверок без ошибок.

### Особенности и ограничения

**Удаление чужого объявления.** Во время тестирования обнаружено, что второй авторизованный пользователь может удалить объявление первого. Сервер возвращает `200`, а последующее получение объявления — `404`. Сценарий помечен как `XFAIL`, поскольку запрет на удаление чужого ресурса явно не сформулирован в доступном контракте DELETE.

**Валидация данных.** Для ограничений, не определённых контрактом, тесты проверяют корректную обработку запроса, не требуя конкретных бизнес-правил без документального основания.

**XSS.** Проверяется обработка строки `<script>alert('XSS')</script>` в поле `name` на уровне API. Проверка выполнения JavaScript в браузере в данный набор автотестов не входит.

**Нестабильность стенда.** Во время повторных запусков наблюдались ошибки `ReadTimeout` при регистрации, создании объявлений и очистке. Причина тайм-аутов не установлена. Подобные ошибки не считаются подтверждёнными дефектами API.
